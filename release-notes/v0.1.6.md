# QuanLLM Harness v0.1.6

## 中文

`v0.1.6` 把可靠性重心从"能恢复"推进到"可控、可测量地恢复"：候选状态显式化并封存失效文本，
最早错误由 Python 定位，领域不变量可注册复用，工具失败不再污染已验证状态，每次运行都输出恢复指标。

主要变化：

- 候选生命周期显式化：求解、综合、修复和领域回写产生的每个候选都有
  `proposed`/`verified`/`invalid`/`archived` 状态与只追加的迁移历史；被判定失效的文本按内容摘要
  封存，后续修复或确定性回写无法把它复活，被拒绝的回写计入失效状态泄漏。
- 最早错误定位：断言按候选顺序线性化为计算依赖时间线；与工具证据矛盾的断言由 Python 直接生成
  定位问题，指明最早错误步骤及其下游待重算断言，且不经过模型裁决，修复指向根因而非下游补偿。
- 修复跨轮证据污染：证据绑定到采集时的候选摘要。claim ID 每轮重发，此前上一轮的反证或支持会被
  错误地匹配到已修复答案（Case 10 类失效状态泄漏），现已隔离。
- 领域不变量注册表：插件新增 `invariants.register` 权限与 `context.invariants.register`；不变量由
  主机确定性执行，只校验经过审查的工具调用所声明的矩阵或概率向量，失败记为基础设施问题而非静默通过。
  官方 `quanllm-qm-teaching` 插件注册投影、幺正、厄米与测量四类可复用不变量。
- 工具可靠性层：Schema 预校验前移，结构非法调用不再消耗语义审查请求；处理器失败按每工具的有界策略
  重试；可选回退实现写入证据；不满足 JSON 可移植性的结果判为证据失败。子进程工具可显式声明重试策略，
  `numeric_integrate` 在默认数值积分失败时回退到有界备用求积策略。
- 诚实降级：数学断言缺少成功工具证据时不再返回 `verified`，而是记录基础设施问题并降级交付；答案文本
  与候选状态不被改写。
- 恢复可观测指标：`HarnessResult`、`--json`、运行记录与 CLI 摘要新增检测方式与延迟、定位断言与来源、
  回滚距离、修复轮数、恢复 Token 开销、失效状态泄漏与恢复是否成功；一次通过的答案不计为恢复成功。

安装或升级核心：

```bash
python -m pip install --upgrade "quanllm-harness==0.1.6"
```

安装量子教学可选后端并启用官方插件：

```bash
python -m pip install --upgrade "quanllm-harness[qm-teaching]==0.1.6"
quanllm-harness plugins enable quanllm-qm-teaching
```

本版本只发布一个 Python wheel (`.whl`) 和一个源码包 (`.tar.gz`)。

## English

`v0.1.6` moves recovery from "possible" to "controlled and measurable": candidate states are
explicit and invalidated text is sealed, the earliest incorrect step is localized by Python,
domain invariants become registered and reusable, tool failures no longer corrupt verified state,
and every run reports recovery metrics.

Highlights:

- Explicit candidate lifecycle. Every solver, synthesis, repair and domain-rewrite candidate carries
  a `proposed`/`verified`/`invalid`/`archived` state with an append-only transition history.
  Invalidated text is tombstoned by content digest, so a later repair or deterministic rewrite cannot
  resurrect it, and rejected write-backs are counted as invalid-state leakage.
- Deterministic earliest-error localization. Claims are linearized into an assertion timeline in
  candidate order; a claim contradicted by tool evidence produces a Python-authored finding that
  names the earliest incorrect step and the downstream assertions that must be recomputed. These
  findings are never adjudicated away, so repair targets the root cause instead of compensating
  downstream.
- Fixed a stale-evidence leak. Evidence is now scoped to the candidate digest it was collected for.
  Claim IDs are re-issued per candidate, so an earlier round's contradiction or support could
  previously be matched against an already repaired answer (the failure pattern behind recovery
  Case 10).
- Domain invariant registry. Plugins gain the `invariants.register` permission and
  `context.invariants.register`. Invariants are host-executed deterministic predicates that only
  validate matrices or probability vectors declared by a reviewed tool call; a failing invariant
  becomes an infrastructure finding instead of silently passing. The official
  `quanllm-qm-teaching` plugin registers reusable projection, unitary, Hermitian and measurement
  invariants.
- Tool reliability layer. Schema pre-validation now rejects structurally invalid calls before a
  semantic-review request is spent; handler failures are retried under a bounded per-tool policy;
  an optional fallback handler is recorded in the evidence; and results that are not JSON-portable
  are rejected as evidence failures. Subprocess tools may declare an explicit retry policy, and
  `numeric_integrate` falls back to a bounded alternate quadrature strategy.
- Honest degradation. A math claim without successful tool evidence no longer reports `verified`; it
  records an infrastructure issue and delivers as degraded. The answer text and the verified
  reasoning state are left untouched.
- Recovery observability. `HarnessResult`, `--json`, run records and the CLI summary now report
  detection kind and latency, localized assertion and source, rollback distance, repair iterations,
  recovery token cost, invalid-state leakage and recovery success. A first-pass answer is
  deliberately not counted as a recovery because no recovery path was exercised.
